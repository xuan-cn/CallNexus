# 意图管理可视化匹配规则

## 配置入口

意图管理 → 新增或修改 →「话术匹配规则」。原有正例、反例话术继续保留，规则为可选项。
本功能不增加 AI 辅助识别开关，不调用 Chat 模型。流程机器人的 AI 辅助理解仍由流程配置控制。

## 使用方式

- 每条规则选择正例命中或反例排除。
- 支持整句一致、包含任意词、同时包含多组词、开头是、结尾是。
- 一组可以添加多个关键词；支持逗号、顿号或换行批量拆分，自动去重。
- 每组默认展示前 6 个词，点击“还有 N 个”展开。
- “同时包含”规则中，组内任意一个词符合即可，组间必须同时符合。
- 默认忽略标点和空格，匹配不区分英文大小写；不向用户开放原始正则。
- 每个意图最多 40 条规则，每条最多 8 组，每组最多 100 个词，每个词最多 128 字。

例：不会上传材料 → 选择同时包含多组词；第一组填“不会、不懂、不知道怎么”，第二组填“上传、提交材料”。
例：家属 → 包含任意词填“爸爸、父亲、妈妈、母亲、爱人”。可配置反例排除“不是他爸爸”等容易误命中的说法。
关键词只做字面匹配，不理解否定关系；请结合反例与测试检查歧义。

## 识别顺序

1. 在当前助手绑定及调用方限定的候选范围内，对每个意图先检查反例整句与反例规则。
2. 未被排除的意图再检查正例整句与正例规则。
3. 只有一个命中时直接返回，不调用向量模型；多个命中时返回规则冲突，供流程澄清或处理未命中，不擅自选择。
4. 无确定性命中时，沿用已有向量识别；被反例排除的意图不会重新参加本次向量匹配。

## 测试

编辑区的“测试规则”直接使用未保存的当前规则，不需要选择助手，也不调用向量或 Chat 模型。
它只测试规则，不测试原有正反例话术；会显示规则序号、匹配方式及命中的词。反例命中优先显示排除。
保存后可以用原有识别测试检查完整候选范围和冲突情况。
测试接口 POST `/api/v1/ai/intents/rules-test` 使用既有 `callcenter:ai-intent:test` 权限，不需要新增菜单权限。

## 部署

需要更新前后端，并在后台启动前通过现有 Flyway 机制应用：
`callnexus-admin/src/main/resources/db/migration/V162__add_intent_match_rules.sql`。
该迁移只给 `cc_ai_intent` 增加可空的 `match_rules_json` 字段，旧意图默认没有规则，不删除旧话术或向量。
本地未对实际数据库执行迁移，也未调用收费服务。
