# 流程机器人节点级控场

## 配置入口

流程编排中选择模板回复、模型回答、知识库问答或意图判断节点，在右侧配置“本节点打断方式”。意图判断的设置用于未命中重问、AI 兜底及上限提示等本节点生成的语音。

| 方式 | 行为 |
| --- | --- |
| 继承 AI 助手 | 使用助手原有打断策略，保留原有通话级控场计数 |
| 禁止打断 | 播报期间不启用打断识别，播完后按流程收音 |
| 允许打断，直接回应 | 停止当前播报，将客户输入交给流程处理 |
| 允许打断，控场替换当前话术 | 丢弃当前节点剩余播报，播放控场替代话术，说完后继续流程 |

选择控场后可填写本节点话术、最多次数（1–20）、冷却时间（0–60000 毫秒）。话术支持现有通话模板变量，留空继承助手话术，助手也为空时使用系统默认话术。节点显式配置优先于助手设置，也适用于该节点作为流程首段播报的情况。

节点自定义控场次数按本次节点执行计算，多个 TTS 分段共用计数；再次执行节点重新计数。达到次数上限或处于冷却期后仍允许普通打断，只是不再插入控场话术。助手继承模式与节点自定义模式分别计数。

上传音频的“播放声音媒体”节点暂未增加此设置；该节点使用独立媒体播放链路。

## 部署与验证

更新前端和 Java 后端，无需 SQL 变更、插件或 Lua 更新。修改流程后保存并发布，使用新通话验证。

1. 连续配置两个模板回复节点，分别填写不同控场话术。各自播报时插话，应播放各自话术。
2. 将第一个节点设置为禁止打断，第二个节点设置为普通打断，验证策略随节点切换。
3. 设置最多控场 2 次、冷却 0 毫秒；第三次插话应停止原播报并处理客户输入，不再控场。
4. 在模型长回答的多个分段中插话，验证原句及剩余分段不再播出，旧模型后续输出也不能重新入队。
5. 在意图判断未命中后的重新询问中插话，验证使用意图判断节点的配置。
6. 未配置节点策略的旧流程应继续遵循助手配置；多通电话的计数互不影响。

Java 日志关键字：`AI 工作流播报节点打断策略`，包含会话 ID、来源节点 ID、策略和是否允许打断。

## 播报结束后误控场修复（2026-10-26）

- Java 优先使用事件自身的 `Application` 与 `Application-Data`，只有没有事件应用名时才回退到通道当前应用，防止并行的 `detect_speech` 覆盖 `speak` 完成事件。不会将两种来源的应用名、参数混搭。
- 控场起声处理增加未关闭、仍等待播报完成、存在有效播放段等条件。已结束播放不能因残留活动段再次触发控场。
- 挂断事件在运行会话尚未创建时也写入结束标记；补齐通道变量后、创建会话时和创建完成后再次检查，避免迟到事件重新启动工作流。结束标记保留 5 分钟。
- 识别插件另行补充 `Sensitivity-Level` 的实际 VAD 映射，标准档位保持原基准阈值。源文件在仓库外层 `plugins/callnexus-recog/src/callnexus_recog_engine.c`，需要重编译 `callnexusrecog.so`，不是 TTS 的 `callnexussynth.so`。

Java 包更新可修复事件误判与生命周期问题；若要使用修复后的灵敏度映射，还须部署识别插件。无需修改 Lua 或数据库。不要在存在通话时重启 UniMRCP。

实拨回归：先等话术完全结束再回答，必须直接进入下一步，不控场、不重播；再在允许打断的节点播报中插话，确认起声后及时停止原播报，控场替代话术说完进入下一节点，不再重播原文。挂断后查看日志，不能为同一客户 UUID 再创建运行会话。

## 控场替代语义

`CONTROL_RESUME` 保留原配置编码以兼容已保存的助手和节点，但行为改为“替换当前话术”，不再续播被打断的当前句或其后续分段。模型回答仍在生成时，旧生成批次作废，其后续分句及异常不能影响已继续执行的流程。

示例：开场白 → 等待输入 → 意图判断。开场白被打断后，播放完整控场替代话术，结束后进入等待输入。达到次数或冷却限制时仍按普通打断处理客户回答，不再控场。控场播报失败时跳过替代播报并继续，不恢复原文。

这项行为变更需要更新 Java 后端；前端更新显示新名称和说明，无需重新编译语音插件、修改 Lua 或执行 SQL。日志关键字为“控场话术已替换当前播报，不再重播原文”。
